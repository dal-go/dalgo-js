Bring the in-browser DTQL engine to parity with the Go engine for ordering and aggregation, proven by a checked-in Go-vs-TypeScript parity suite (`test/parity`, expectations generated from dalgo v0.88.2 by `tools/parity/regenerate.sh`).

New: `orderBy` accepts expression keys (for example a binary `/` over aggregates, with `desc`) alongside field keys; a column's `as` alias can be used as an `orderBy` key and as a `having` operand; `having` accepts any expression (for example a `binary` ratio); aggregate queries are validated at parse like Go's `ValidateAggregation` (non-grouped field or expression, nested aggregates, `sum(*)`, `DISTINCT` on `min`/`max`/`first`/`last`, a plain column beside an aggregate-only key all fail with a located `join_aggregate at orderBy[0]: ...` error); an unknown property on an order key (`descending`, `direction`, `as`, `source` without `field`), a `star` or a `param` key is rejected at parse instead of being ignored; unknown properties inside any expression are rejected too; an aggregate query without `columns` returns its group keys (an ungrouped one returns one empty row) instead of the first row of each group; DISTINCT aggregates over a flat join run through the generic plan under `scanPages` instead of failing. Fixed: the streaming (`scanPages`) plan sorted field keys by the projected column name, so a renamed or omitted column left rows unsorted; it also leaked an internal `sortKeys` field on results without an `ORDER BY`, and returned no row for an aggregate over zero rows without a `groupBy`.

`DTQLQueryOrder` is now the union `DTQLFieldOrder | DTQLExpressionOrder`: code that read `order.field` must narrow on `order.expression`.

Behaviour changes, all to match Go: arithmetic on a null or non-numeric operand, and division by zero, evaluate to null (division by zero was `Infinity`, text operands threw); mixed-type values order as booleans, then numbers, then strings (it was strings, numbers, booleans); `sum` over a group with no numeric values is null (it was 0) and `sum`/`avg` ignore non-numeric values (they threw); `first`/`last` keep a null value; `where` and `having` comparisons `<`, `<=`, `>`, `>=` are false when either side is null (null used to sort below everything and so satisfied `< x`); an unqualified field on an aliased single source now resolves to that source instead of being left as a bare string. Queries that Go rejects for an invalid aggregate shape (for example a plain column that is not in `groupBy`) now also fail in `parseDTQL`.
